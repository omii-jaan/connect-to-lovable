1. CORE PHILOSOPHY & ANTI-SLOP GUARDRAILS
================================================================================

Amateur AI code ("Vibe Coding" or "AI Slop") relies on heavy visual noise, fake 
hero metrics, arbitrary gradients, neon-on-dark text, and random border-radii 
to mask a lack of functional depth.

Top-tier engineering teams (Stripe, Linear, Vercel, Apple) build products with 
mathematical, optical, and mechanical precision:

[BANNED PATTERNS / ANTI-SLOP RULES]
- NO decorative blue-to-purple gradients, glassmorphism overlays, or glowing halos.
- NO nested cards (a card wrapped inside another card).
- NO thick visual left-border accents on cards combined with rounded corners.
- NO arbitrary box-shadows; shadows must represent calculated Z-axis altitude.
- NO line-wrapped or truncated labels inside pill buttons or badge controls.
- NO decorative "01, 02" step numbers unless strictly sequential and functional.
- NO hero eyebrows (tiny tracked-out uppercase phrases above main titles).
- NO generic marketing speak ("supercharge", "empower", "next-gen").

[ELITE PRINCIPLES]
- Functional Purpose First: Every pixel, spacing unit, and border exists to 
  establish visual structure or convey information.
- Mathematical Rhythms: Spacing, font sizes, and container padding follow explicit 
  mathematical ratios (4px/8px grid system).
- Optical Calibration: Alignment is optical, not just box-model CSS alignment.
- High Information Density: Clean, dense layouts with crisp boundaries and 
  tabular data presentation.

2. DESIGN SYSTEM ARCHITECTURE & DESIGN TOKENS
================================================================================

A production-grade design system uses CSS Custom Properties (Variables) mapping 
HSL or OKLCH color spaces. Hardcoded hex values in inline styles or components 
are strictly prohibited.

2.1 COLOR SYSTEM & ALTITUDE (LIGHT & DARK MODES)
--------------------------------------------------------------------------------
Dark mode backgrounds must not use pure `#000000`, and light mode backgrounds 
must avoid pure `#FFFFFF` as a default canvas. A <3-5% saturation warm or cool 
tint is added to eliminate eye fatigue.

Color Contrast Rules:
- WCAG AA standard: 4.5:1 minimum contrast ratio for standard body text.
- WCAG AAA standard: 7:1 for critical actionable text.
- Surface altitude rules: Elements closer to the user on the Z-axis (modals, 
  popovers) get lighter surface values in dark mode and subtle elevation in light.
- Max brightness delta: Background-to-container delta is <= 12% in dark mode and 
  <= 7% in light mode.

Sample Token Architecture (CSS Custom Properties):
  --bg-base:          hsl(220, 15%, 8%);
  --bg-surface:       hsl(220, 14%, 12%);
  --bg-elevated:      hsl(220, 13%, 16%);
  --border-subtle:    hsl(220, 10%, 20%);
  --border-strong:    hsl(220, 12%, 30%);
  --accent-primary:   hsl(172, 80%, 40%); /* Muted Teal #14B8A6 */
  --text-primary:     hsl(220, 15%, 96%);
  --text-secondary:   hsl(220, 10%, 70%);
  --text-tertiary:    hsl(220, 8%, 50%);

2.2 CORNER NESTING MATHEMATICS
--------------------------------------------------------------------------------
When a rounded container sits inside another rounded container, the inner radius 
MUST be calculated mathematically to preserve parallel visual curves:

  Inner Radius = Outer Radius - Padding

Example:
  Outer Container Radius = 16px
  Container Padding = 12px
  Calculated Inner Child Radius = 16px - 12px = 4px.

Failing to calculate inner radius results in visually jarring "squircle" distortions.

2.3 SPACING RHYTHM & PADDING MATH
--------------------------------------------------------------------------------
- Standard Grid Unit: 4px / 8px base rhythm.
- Container Outer Padding Rule: Outer padding MUST always equal or exceed the 
  inner spacing between child elements.
- Button Padding Rule: Horizontal button padding is exactly 2x vertical padding 
  (e.g., `px-4 py-2` or `px-6 py-3`).

3. TYPOGRAPHIC SCALING & MICRO-TYPOGRAPHY
================================================================================

3.1 TYPE SCALES
--------------------------------------------------------------------------------
Type sizes must follow standard mathematical step ratios rather than arbitrary 
pixel sizes:
- Product UI (High density): Major Second (1.125) or Minor Third (1.200) ratio.
- Display/Marketing: Perfect Fourth (1.333) or Golden Ratio (1.618).

Step Ratio Example (Minor Third 1.200, Base 16px):
- Caption:   13.3px (0.833rem)
- Body:      16.0px (1.000rem)
- H4:        19.2px (1.200rem)
- H3:        23.0px (1.440rem)
- H2:        27.6px (1.728rem)
- H1:        33.2px (2.074rem)
- Display:   39.8px (2.488rem)

3.2 MICRO-TYPOGRAPHY & TABULAR DATA
--------------------------------------------------------------------------------
- Numeric Readability: ALL financial data, timestamps, commit counts, prices, and 
  metric tables MUST use tabular numbers (`font-variant-numeric: tabular-nums` or 
  `font-mono`). This prevents layout jitter when numbers change.
- Line Length (Measure): Body text line lengths MUST be constrained between 65 
  and 75 characters (`max-w-[65ch]`) to maintain optimal readability.
- Line Height (Leading): Body text leading must be 1.5 - 1.7. Headings must use 
  tight leading (1.1 - 1.25).
- Single-Line Label Rule: Text inside buttons, tabs, pills, chips, or badges 
  MUST sit on ONE single line (`white-space: nowrap`). Truncation or wrapping inside 
  a small control is classified as a UI defect.

4. UI/UX INTERACTION & MOTION ENGINEERING
================================================================================

4.1 MOTION TIMING & EASING CURVES
--------------------------------------------------------------------------------
Animations in professional software communicate state changes without delaying 
the user:

Duration Tokens:
- Micro Interactions (Hover, Toggle, Checkbox): 100ms - 150ms
- Structural Transitions (Dropdown, Tooltip, Collapse): 200ms - 250ms
- Page Layout Shifts / Modal Entry: 300ms - 350ms

Easing Curve:
  cubic-bezier(0.4, 0.0, 0.2, 1) /* Standard material motion curve */

Reduced Motion:
All animated components MUST respect user accessibility settings via CSS 
`@media (prefers-reduced-motion: reduce)` or React `useReducedMotion()`.

4.2 MICRO-FEEDBACK LOOPS & FEEDBACK STATES
--------------------------------------------------------------------------------
1. Optimistic UI Updates: UI responds instantly to user input (e.g., liking a post, 
   starring a repository) before backend confirmation, rolling back gracefully 
   if the API call fails.
2. Skeleton Loading States: Skeleton shapes must match the exact dimensions of 
   the content being loaded to prevent cumulative layout shift (CLS = 0).
3. Debounced Action Feedback: Auto-saving or search queries debounce inputs 
   (300ms) with clear status indicators ("Saving...", "Saved", "Offline").
4. Active Focus Rings: High-contrast 2px focus ring (`focus-visible:outline-none 
   focus-visible:ring-2 focus-visible:ring-primary`) on all interactive controls.

5. FRONTEND COMPONENT ARCHITECTURE & STATE MANAGEMENT
================================================================================

5.1 COMPONENT MODULARITY & ATOMIC BOUNDARIES
--------------------------------------------------------------------------------
Top teams enforce strict modular separation. Monolithic single-file apps are 
strictly prohibited:

- Atomic Hierarchy:
  - `/src/components/ui/` -> Basic primitive components (Button, Input, Badge, Modal)
  - `/src/components/`    -> Domain components (ProjectCard, BuilderHeader, FeeFeed)
  - `/src/pages/`         -> Page views binding data and layout together
  - `/src/types/`         -> Global TypeScript definitions and domain models

5.2 STATE SEPARATION STRATEGY
--------------------------------------------------------------------------------
1. Server State: Database queries, API payloads, real-time sync (Firebase / 
   React Query).
2. URL State: Search filters, tab selection, page pagination belong in URL query 
   params so links are shareable.
3. Component Local State: Ephemeral UI states (isOpened, activeHover, form inputs).
4. Global Context: User Auth session, global theme settings, global toast system.

5.3 STRICT TYPESCRIPT STANDARDS
--------------------------------------------------------------------------------
- Never use `any`. Use `unknown` or explicit generics when dealing with unparsed data.
- Derive component props from backend database interfaces or schema types.
- Use discriminated unions for status-driven component UI states:

  type AsyncState<T> =
    | { status: 'idle' }
    | { status: 'loading' }
    | { status: 'success'; data: T }
    | { status: 'error'; error: Error };

6. PERFORMANCE, ACCESSIBILITY, AND OPTICAL ERGONOMICS
================================================================================

6.1 ACCESSIBILITY (A11Y)
--------------------------------------------------------------------------------
- Touch Target Ergonomics: All interactive elements on touch screens MUST have a 
  minimum hit area of 44px x 44px. Desktop button height minimum is 32px - 36px.
- ARIA Roles & Screen Readers: Icon-only buttons MUST have `aria-label` or 
  `<span className="sr-only">`.
- Live Announcers: Real-time updates (notifications, badges) use `aria-live="polite"`.
- Keyboard Navigation: Every page must be 100% navigable using Tab, Enter, Space, 
  and Arrow keys. Skip-to-main-content links must exist at the document root.

6.2 CANVAS & RESIZE ERGONOMICS
--------------------------------------------------------------------------------
- Canvas, chart, and stage containers MUST use `ResizeObserver` for fluid 
  re-renders rather than listening to `window.innerWidth`.
- Layouts must be desktop-first in density precision, mobile-first in code execution.

7. PRODUCTION QA, CODE REVIEWS, AND SHIPYARDS WORKSPACE INTEGRATION
================================================================================

7.1 DEFINITION OF DONE (TIER-1 QUALITY CHECKLIST)
--------------------------------------------------------------------------------
Before declaring any feature complete:
[ ] Zero console errors or unhandled promise rejections.
[ ] Clean compilation & linter output (`npm run lint` and `compile_applet`).
[ ] Responsive verification across desktop (1440px), tablet (768px), and mobile (375px).
[ ] Tested in unauthenticated (guest) mode AND authenticated user mode.
[ ] Firestore Security Rules written and deployed for every new collection.
[ ] Tabular numbers used for metrics; no line-wrapped label text inside badges.
[ ] Fast initial paint with zero CLS (Cumulative Layout Shift).
